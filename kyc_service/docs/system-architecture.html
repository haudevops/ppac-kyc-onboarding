Sơ đồ kỹ thuật hệ thống KYC Onboarding

Hai source: kyc_app (Flutter, Android / iOS) và kyc_service (TypeScript, Express 5, Prisma) chạy trên Cloudflare: Workers cho API, D1 cho database, R2 cho ảnh và Durable Object cho job xét duyệt. Khi dev ở máy local (npm run dev) cùng source đó chạy như server Node với SQLite và ổ đĩa.

Kiến trúc tổng quan State machine Luồng đăng nhập Luồng nộp hồ sơ Upload trực tiếp Bảng giao tiếp

1. Kiến trúc tổng quan

App chỉ nói chuyện với một điểm duy nhất là Worker qua HTTPS /api/v1, kể cả khi tải ảnh (URL /api/v1/files/:token ký HMAC, hết hạn sau 5 phút). Worker truy cập D1, R2 và Durable Object qua binding, không cần API key. Trong mỗi hệ thống, phụ thuộc chỉ hướng vào trong (app: presentation → domain ← data; backend: controller → service → repository); chỉ thư mục worker/ biết mình đang chạy trên Cloudflare.

Mobile app Backend API Object storage Database Tài khoản Cloudflare Gọi trực tiếp / binding Kích hoạt bất đồng bộ

2. State machine của hồ sơ KYC

Khai báo một lần trong src/models/kyc.model.ts. Mỗi chuyển trạng thái là một UPDATE … WHERE id = ? AND status = ? có điều kiện, kèm một dòng KycStatusHistory, nên không bao giờ bị áp dụng hai lần (D1 không có interactive transaction nên hai câu lệnh chạy lần lượt; an toàn khi chạy đồng thời vẫn giữ nguyên).

3. Luồng đăng nhập, refresh token và đăng xuất

Access token 15 phút; refresh token được xoay vòng mỗi lần dùng, chỉ lưu hash. AuthInterceptor gom các lỗi 401 đồng thời vào một lần refresh duy nhất.

4. Luồng lưu nháp, upload ảnh, nộp hồ sơ và xét duyệt

Khi nộp hồ sơ, Worker đánh thức Durable Object KycReviewScheduler; alarm của nó chạy KycReviewWorker.tick() mỗi giây đến khi không còn hồ sơ chờ (thêm Cron mỗi phút để dự phòng). Trạng thái nằm trong D1 nên deploy lại hay restart cũng không mất hồ sơ đang chờ. App polling trạng thái bằng rxdart (startWith + exhaustMap + takeWhileInclusive).

5. Upload bằng URL đã ký (tuỳ chọn, ngoài cách multipart)

Trên Cloudflare, URL ký là của chính Worker (/api/v1/files/:token, HMAC, 10 phút): Worker kiểm tra chữ ký và Content-Type rồi ghi vào R2, nên không cần cấp API key R2. Kích thước và loại file thật được kiểm tra lại ở bước confirm. (Khi chạy server Node với STORAGE_DRIVER=s3, URL trỏ thẳng tới presigned URL của R2 / S3.)
